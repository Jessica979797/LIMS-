## 问题 1：i18n 后 `pnpm tsc` 报 61 个错误（均为误报）

### 现象
启用 UmiJS `locale` 插件、给所有页面接入 `useIntl` 后，`pnpm tsc` 报 61 个错误（i18n 前为 37 个）。

### 排查
错误码分布：48× `TS2305`（模块无导出成员）+ 12× `TS7006`（隐式 any）+ 1× `TS2304`。全部指向 `@umijs/max` 的 `useIntl / setLocale / getLocale / useAccess / useModel / history / request / RunTimeLayoutConfig / RequestConfig` 等。

### 根因
UmiJS 的导出由 `src/.umi` 临时类型生成，**原生 `tsc` 不像 `pnpm dev` / `pnpm build`（走 umi 工具链）那样解析它们**。新增 locale 后 `.umi` 未重生成，`useIntl` 等也加入误报行列；`.map` 隐式 any 是 `request` 导入失败的级联。

### 解决
- 判断标准：只要错误全是 `TS2305 / TS7006 / TS2304`，没有 `TS2322 / TS2339 / TS2554` 等真实类型错误，就是干净的。
- `pnpm build`（exit 0）是最终判据，会重生成 `.umi` 并通过。
- **不要去"修"这些 `@umijs/max` 错误**，那是 umi 工具链配置特性。

### 预防
已写入项目记忆 `pnpm-tsc-false-positives.md`。

## 问题 2：`antd.configProvider: true` 配置校验失败

### 现象
为启用运行时 antd 主题切换，在 `.umirc.ts` 加 `antd.configProvider: true`，`pnpm build` 报 `Invalid input`（path: `configProvider`）。

### 根因
UmiJS antd 插件的 schema 是 `configProvider: zod.record(zod.any())`，要**对象 / record**，不是布尔值。

### 解决
改为 `configProvider: {}`。插件会自动把静态 `theme` 合并进 `configProvider.theme` 作为运行时 ConfigProvider 的初始态。

### 经验
Umi 配置项的值类型要以插件 schema 为准（record vs boolean vs string），报 `Invalid input` 多半是值类型不对，去 `node_modules/@umijs/plugins/dist/<plugin>.js` 查 schema。

## 问题 3：黑模式下页面白屏（最重要）

### 现象
主题切换功能上线后，切到黑模式页面不展示（白屏），`/cs/applications` 等页面受影响。

### 排查过程
1. 业务页代码本身无误——`STATUS_MAP` / `APP_NEXT_LABEL` 都有空值保护，`pnpm build` 通过，排除编译错误，定位为**运行时问题**。
2. 审查 `app.tsx` 主题应用逻辑：`useAntdConfigSetter()` 返回的 setter 放进了 `useEffect` 依赖 `[theme, setAntdConfig]`。
3. 查生成的 `src/.umi/plugin-antd/runtime.tsx`，发现 `setAntdConfig` 是 `AntdProvider` **组件体内每次渲染新建**的包装函数：
   ```ts
   const setAntdConfig = (newConfig) => {
     _setAntdConfig(prev => merge({}, prev, typeof newConfig === 'function' ? newConfig(prev) : newConfig))
   }
   ```
   即**非稳定引用**。

### 根因
**无限渲染循环**：effect 触发 → `setAntdConfig` 改状态 → `AntdProvider` 重渲染 → setter 引用变 → effect 依赖变 → effect 再触发 → React "Maximum update depth exceeded" → 白屏。
> 注：白底其实也会触发，只是切到黑底才注意到。

### 解决
把 `setAntdConfig` 移出 `useEffect` 依赖，effect 只在 `[theme]` 变化时跑一次：
```ts
useEffect(() => {
  setAntdConfig((prev) => ({ ...prev, theme: buildAntdTheme(theme) }));
  document.documentElement.dataset.theme = theme;
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [theme]);
```

### 预防
已写入项目记忆 `umi-antd-config-setter-unstable.md`。**教训：Umi 运行时生成的 hook 返回值未必稳定，放进 effect 依赖前要确认其引用稳定性。**

## 问题 4：Edit 工具字符串匹配失败（箭头 / 全角字符）

### 现象
编辑 `reagent.ts`、`de-DE.ts` 时，`old_string` 含 `->`（U+2192）或全角括号的注释行匹配失败，工具提示"neither form matched"。

### 根因
文件里的箭头是 Unicode 字符，与输入的 ASCII `->` 字节不同；Read 显示看起来一样但实际不一致。

### 解决
- 改用**更小、不含该字符的锚点**（如只匹配 `report: REAGENT.pink, // 报告\n} as const;`）。
- 或重新 Read 拿到精确字节再匹配。
- 大段重写时直接用 Write 整文件覆盖，规避匹配问题。

## 问题 5：locale 文件键名笔误与重复键

### 现象
- `zh-CN.ts` 中 `status.report.APPROved`（大小写错误，应为 `APPROVED`）。
- `de-DE.ts` 中 `shell.lab.tasks.desc`、`shell.lab.items.title` 重复定义。

### 解决
- 笔误：`APPROved` → `APPROVED`。
- 重复键：删除多余行，保留一份。
- 用脚本比对"用到的 id"vs"定义的 key"，确保 0 缺失：
  ```bash
  grep -hoE "id: '[a-zA-Z0-9._]+'" src/pages src/components src/app.tsx -r | sort -u > /tmp/used.txt
  grep -oE "^  '[a-zA-Z0-9._]+'" src/locales/zh-CN.ts | sort -u > /tmp/defined.txt
  comm -23 /tmp/used.txt /tmp/defined.txt   # 应为空
  ```

### 经验
i18n 的 `formatMessage({ id })` 的 id 是字符串，**tsc 查不出缺失的键**，必须用脚本比对 used vs defined。动态拼接的键（如 `'role.module.' + r.module`）要单独核对前缀。

## 问题 6：PageShell 包裹 ProTable 后「模式 B」缩进错乱

### 现象
模式 B（单个自闭合 `<ProTable />`，无 `<>` 片段）的 approval / audit 页，包裹 PageShell 后 ProTable 属性行没跟着 +2 缩进。

### 根因
模式 A 的 `<>` → `<PageShell>` 直接保留缩进即可；模式 B 没有 `<>`，ProTable 从 4 空格移到 6 空格，但其属性行没同步。

### 解决
用 Write 整体重写这两个文件，统一缩进。功能不受影响（JSX 不关心缩进），仅为源码整洁。

## 问题 7：左侧菜单不随语言切换

### 现象
启用 i18n、路由 `name` 改为 `menu.*` 键后，左侧菜单不随语言切换（显示原始 key 或始终不翻译）。

### 排查
1. 看生成的 `src/.umi/plugin-layout/Layout.tsx`：`menu={{ locale: userConfig.locale }}`，而 `userConfig` 是静态配置 `{ title:'LIMS' }`，没设 `locale`，故 `menu.locale` 为 `undefined`。
2. 更深：查 ProLayout 压缩源，菜单翻译逻辑是：
   ```js
   var f=d.name; return !1!==u.locale && d.locale && i && (f=i({id:d.locale, defaultMessage:d.name}))
   ```
   即翻译用的是 **`item.locale` 字段**（不是 `item.name`），且仅当 `menu.locale !== false` 且 item 有 `locale` 字段时才翻译。
3. UmiJS 给菜单项只设了 `name`（= 路由 `name` = `menu.*` 键），**没设 `locale`**，所以不翻译。

### 根因
ProLayout 用 `item.locale` 翻译菜单名，而 UmiJS 生成的菜单项缺少 `locale` 字段；且 `menu.locale` 未显式开启。

### 解决
在 `app.tsx` 的 layout 运行时配置加 `menuDataRender`，递归给每个菜单项补 `locale = item.name`（即 `menu.*` 键），并显式 `menu: { locale: true }`（经 `{...runtimeConfig}` 覆盖原 `undefined`）。ProLayout 用其 `formatMessage`（来自 `useIntl`，随语言切换）按 `item.locale` 翻译。无需在 layout 函数里调 hooks。

### 经验
ProLayout 菜单 i18n 看的是 `item.locale`，不是 `item.name`；UmiJS 只设 `name`，需自己用 `menuDataRender` 补 `locale`。

## 问题 8：头像"系统管理员"不随语言切换

### 现象
右上角头像旁（语言切换器旁边）的"系统管理员"不随语言切换。

### 排查
全局搜索"系统管理员"--不在前端源码、不在 `.umi` 生成文件、不在工作区后端文件。确认是后端 `/api/auth/profile` 返回的 `currentUser.name`（值正好是角色名"系统管理员"）。它不是 i18n 键，自然不切换。

### 根因
头像直接显示 `currentUser.name`（后端数据，角色名），未走 i18n。后端返回的角色名/枚举标签不是翻译键。

### 解决
头像改为按 `currentUser.roles[0]` 映射到本地化角色标签：
- 三语 locale 文件加 `role.label.*` 键（11 个角色：`system_admin` → 系统管理员 / System Administrator / Systemadministrator，等）。
- `app.tsx` HeaderActions 用 `formatMessage({ id: 'role.label.${roles[0]}', defaultMessage: name })` 得到 `displayName`，头像文字与字母均用 `displayName`。
- 找不到角色键时回退到原始 `name`（真实人名仍保留）。

### 经验
后端返回的角色名/枚举标签要做 i18n，需前端按角色 code 映射到本地化键，不能直接显示后端文案。

## 关键经验汇总

| # | 经验 | 应用 |
|---|------|------|
| 1 | `@umijs/max` 的 hook/类型在 `.umi` 里，原生 `tsc` 看不到 | 用 `pnpm build` 判真假错误，别被 TS2305 误导 |
| 2 | Umi 运行时 hook 返回值可能非稳定引用 | 勿盲目放 `useEffect` 依赖，否则无限渲染白屏 |
| 3 | Umi 配置项值类型看插件 zod schema | 报 `Invalid input` 多半是 record/boolean 类型不对 |
| 4 | i18n 键完整性 tsc 查不出 | 用脚本比对 used vs defined keys |
| 5 | 多语言/主题改动量大 | 子代理批量重构机械部分，自己写核心并校验 |
| 6 | Edit 匹配含 Unicode 特殊字符的行易失败 | 用更小锚点或直接 Write 覆盖 |
| 7 | ProLayout 菜单 i18n 看的是 `item.locale` 不是 `item.name` | UmiJS 只设 name，需 `menuDataRender` 补 `locale` + `menu:{locale:true}` |
| 8 | 后端返回的角色名不是 i18n 键 | 前端按角色 code 映射到本地化键（`role.label.*`），别直接显示后端文案 |
